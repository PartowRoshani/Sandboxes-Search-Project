# سورس‌کد پروژه جعبه‌های شن

این پوشه حاوی سورس کامل مدل بدون آب پروژه هوش مصنوعی است. برای اجرا به Python نسخه 3.10 یا جدیدتر نیاز دارید.

## 1. نصب

از داخل پوشه اصلی پروژه:

```bash
python -m pip install -r requirements-dev.txt
```

در ویندوز می‌توانید در PowerShell دستور `py -m pip install -r requirements-dev.txt` را اجرا کنید.

## 2. اجرای سریع

```bash
python main.py
```

این دستور مثال استاد را با UCS حل می‌کند و فایل `results/demo.html` را می‌سازد. این فایل را در مرورگر باز کنید تا حرکت‌ها را گام‌به‌گام ببینید.

## 3. مقایسهٔ روش‌های اجباری و امتیازی

```bash
python main.py compare --example professor --limit-seconds 2
```

این اجرا همهٔ الگوریتم‌های Greedy استاد، DFS، BFS، IDS، UCS، A* و RBFS را مقایسه می‌کند. روش‌های DFS/BFS/IDS الزاما هزینهٔ کمینه ندارند. RBFS نیز ممکن است با رسیدن به محدودیت منابع پایان یابد.

## 4. یک حالت دلخواه یا تصادفی

در ورودی استاندارد 0=پر، 0.5=نیمه‌پر، 1=خالی است.

```bash
python main.py solve --rows 2 --cols 2 --grid '[[0,1],[0.5,0]]' --algorithm ucs --html results/custom.html
python main.py solve --rows 5 --cols 2 --seed 42 --algorithm astar --html results/random.html
```

در مثال استاد، مقادیر 1 و 0 ظاهرا برعکس قرارداد اولیه استفاده شده‌اند؛ دستور `--example professor` قرارداد مخصوص مثال را اعمال می‌کند. فرمول هزینه با میزان شن (نه کد نمایشی) محاسبه می‌شود.

## 5. بررسی همهٔ 59049 حالت اولیه در شبکه 5×2

```bash
python main.py analyze --rows 5 --cols 2 --output results/exhaustive_5x2
```

نتایج بهینه با Dijkstra معکوس روی فضای حالات معتبر، شامل درهای عمودی بازمانده، محاسبه می‌شوند. خروجی شامل جدول CSV برای تمام حالات اولیه و هیستوگرام نسبت هزینه حریصانه به بهینه و دو نمودار پراکندگی است. حالت بدون شن از محاسبهٔ نسبت حذف می‌شود چون نسبت 0/0 تعریف ندارد.

## 6. معیارسنجی الگوریتم‌ها از نظر زمان و حافظه

```bash
python main.py benchmark --count 30 --limit-seconds 0.35 --output results/benchmark.csv
```

برای انجام معیارسنجی جداگانهٔ تمام الگوریتم‌ها روی تمام 59049 حالت:

```bash
python main.py benchmark --all --limit-seconds 0.2 --output results/benchmark_all.csv
```

گزینه `--all` ممکن است بسیار طولانی باشد. خروجی مرحله‌به‌مرحله ذخیره می‌شود و در صورت اجرای مجدد از رکوردهای ثبت‌شده عبور می‌کند. محدودیت زمانی و تعداد گسترش گره ممکن است بعضی سطرها را به status=timeout یا expansion_limit برساند.

## 7. آزمون‌های خودکار

```bash
python -m pytest -q
```

## معماری کد

- `main.py`: نقطهٔ شروع ساده.
- `sandgrid/model.py`: تعریف حالت، انتقال‌ها، درهای عمودی بازمانده و تابع هزینه.
- `sandgrid/search.py`: الگوریتم‌های هفت‌گانه.
- `sandgrid/cli.py`: پردازش آرگومان‌های خط فرمان.
- `sandgrid/visualize.py`: خروجی HTML آفلاین و GIF.
- `sandgrid/batch.py`: یافتن جواب بهینه همهٔ حالات و ساخت نمودارها.
- `sandgrid/benchmark.py`: ارزیابی زمان و حافظه.
- `tests/test_model.py`: آزمون صحت.
- `docs/proposed_model.md`: توضیح فرض‌های شفاف‌سازی حرکت شن.

## یادداشت فنی

حالت اصلی **بدون آب** پیاده‌سازی شده است؛ حالت آب/بتن اختیاری هنوز اجرا نشده است. برای حرکت شن در درهای عمودی بازمانده فرض «جریان فوری تا تثبیت یا خروج شن» به کار رفته است. نتیجه بهینه تابع همین فرض است. مثال استاد برای Greedy هزینه 47 را بازتولید می‌کند؛ برای تفسیر متفاوت از اتصال درها، لازم است منطق انتقال در `model.py` اصلاح شود.
